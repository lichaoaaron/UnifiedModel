# MModel Vision

## 产品定位

MModel 是一款独立的运维语义层与故障调查平台。

MModel 不直接承担底层日志、指标、Trace 的采集、存储和展示职责，而是在这些运行时数据之上构建统一的对象语义、对象关系、证据关联和调查上下文，让运维人员、平台能力、CLI、Agent 和大模型围绕同一套运行时对象模型协同工作。

## 为什么做

现代 IT 系统的故障调查通常分散在多个数据入口、多个对象体系和多套查询方式中。用户知道有日志、指标和 Trace，但并不总能快速回答以下问题：

- 现在出问题的到底是哪个运行对象。
- 这个对象依赖谁、被谁依赖。
- 某个时间点真实存在的运行拓扑是什么。
- 与该对象相关的证据应该去哪里找。
- Agent 或大模型应基于什么上下文给出可信诊断。

MModel 通过统一运行时对象模型，把复杂系统理解和故障调查从“面向数据源”转为“面向对象与关系”。

## 愿景

- 让用户先看到对象，再看到证据。
- 让查询先围绕 Entity、Relation、Topology，再映射到底层数据。
- 让 AI 先获取结构化上下文，再生成诊断结论。
- 让任何平台集成都共享同一套 MModel Core 能力，而不是复制一套平台专用逻辑。

## 产品边界

MModel 负责：

- Runtime Entity Model
- Entity / Relation / Topology
- Evidence 关联
- Historical Runtime
- Query API
- Diagnosis API
- Web / CLI / Agent 的统一能力层

外部平台负责：

- 登录与会话
- 菜单入口与导航
- 时间范围同步
- 深链跳转
- 原始数据视图承接

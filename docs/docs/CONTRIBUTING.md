# MModel Product Docs Contributing

## 目标

本目录用于约束产品需求与平台适配文档的编写方式，帮助外协团队、研发团队和集成团队在同一产品边界下协作。

## 基本原则

- MModel 是独立产品，不把任何宿主平台写成产品本体。
- 所有核心能力优先沉淀在 MModel Core。
- 平台集成只负责登录、导航、上下文同步和原始数据跳转。
- 文档描述用户价值，不只描述技术实现。

## 文档更新规则

- 新增核心能力时，先更新 `prd.md`。
- 涉及平台边界调整时，同时更新 `architecture.md` 与 `api.md`。
- 涉及页面变化时，同时更新 `ui.md`。
- 涉及阶段目标变化时，同时更新 `roadmap.md`。

## 外协开发约束

- 不得把核心业务逻辑写入平台插件或平台适配器。
- 不得为单个平台单独定义对象模型。
- 不得绕过 MModel Core 直接在宿主平台中拼装对象、证据和诊断逻辑。
- 任何新增接口都应能映射到 Query API、Diagnosis API 或 Integration API。

## 交付物要求

- 需求说明必须明确核心能力与平台集成能力的归属。
- 页面设计必须对应到对象、拓扑、证据和诊断主链路。
- 接口设计必须优先面向 Entity、Relation、Evidence、Topology 和 Context。

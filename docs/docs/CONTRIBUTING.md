# MModel 外协协作约束

## 目标

本目录用于约束产品需求与平台适配文档的编写方式，帮助外协团队、研发团队和集成团队在同一产品边界下协作。

## 基本原则

- 当前文档默认将 MModel 作为相对独立的产品能力进行描述，不把宿主平台直接写成产品本体。
- 当前文档建议将核心能力优先沉淀在 MModel Core。
- 结合第一阶段目标，平台集成侧当前主要负责登录、导航、上下文同步和原始数据跳转。
- 文档必须描述用户价值和职责边界，而不只描述技术实现。

## 文档更新规则

- 新增核心能力时，优先更新 `prd.md`。
- 涉及平台边界调整时，同时更新 `architecture.md` 与 `api.md`。
- 涉及页面结构变化时，同时更新 `ui.md`。
- 涉及阶段目标变化时，同时更新 `roadmap.md`。
- 涉及视觉参考变化时，同时更新 `reference-screenshots.md`。

## 外协开发约束

- 当前版本建议不要把核心业务逻辑优先写入平台插件或平台适配器。
- 当前版本建议避免为单一平台单独定义对象模型。
- 当前版本建议避免绕过 MModel Core，直接在宿主平台中拼装对象、证据和诊断逻辑。
- 任何新增接口都应能映射到 Query API、Diagnosis API 或 Integration API。

## 交付物要求

- 需求说明必须明确区分 MModel Core 与平台集成能力。
- 页面设计必须对应对象、拓扑、证据、时间线和诊断主链路。
- 接口设计必须优先面向 Entity、Relation、Evidence、Topology 和 Context。
- 若采用参考截图，必须说明其参考目的与不直接继承的部分。

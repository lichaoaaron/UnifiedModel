# MModel UI

## 目标

Web UI 为运维人员提供对象驱动的调查界面，使用户无需命令行即可完成对象定位、关系分析、证据查看和诊断协同。

## 核心页面

- 对象地图
- 对象详情
- 拓扑浏览
- 调查时间线
- Evidence 浏览
- Diagnosis 页面
- 调查报告页面

## 页面结构

### 实体探索

实体探索负责“看清对象”，建议包含以下核心页面或标签：

- 概览
- 拓扑
- 健康
- 证据
- 调查时间线

其中，调查时间线用于以对象为中心统一展示相关 Metrics、Logs、Traces、Events、Topology Changes 和 Diagnosis Steps，帮助用户还原故障发生与收敛过程。

### 智能运维

智能运维负责“围绕对象完成调查任务”，建议以结构化调查结果页为主，而不是以对话界面为主。

建议包含：

- 诊断结果视图
- 影响面分析视图
- 调查报告视图

如果需要集成对话助手，应作为侧边栏、抽屉或外部助手入口接入，而不是替代 MModel 的结构化调查界面。

## MModel vs Copilot 职责边界

### MModel UI 负责

- 实体探索主界面
- 对象详情与对象视图切换
- 拓扑浏览与拓扑快照
- 健康与证据聚合视图
- 调查时间线视图
- 结构化诊断结果、影响面和报告结果页

### Copilot UI 负责

- 通用聊天窗口
- 多轮追问
- 对调查结果进行自然语言解释
- 帮助用户总结时间线、根因和报告措辞

### 协作关系

- MModel 提供结构化调查上下文与页面结果。
- Copilot 调用 MModel Skill / MCP / API，并对这些结果做自然语言交互。
- Copilot 不替代 MModel 的对象、证据、拓扑和时间线视图。

## 关键交互

- 全局对象搜索
- 时间范围切换
- 从对象跳转拓扑
- 从对象跳转调查时间线
- 从时间线事件联动证据详情
- 从时间线关键时刻联动拓扑快照
- 从拓扑跳转证据
- 发起 AI 诊断
- 查看影响面
- 生成调查报告

## 设计原则

- 先对象，后证据。
- 同一对象的拓扑、证据和诊断上下文可连续切换。
- 平台嵌入与独立访问保持一致信息结构。

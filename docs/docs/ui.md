# MModel 页面与交互说明

## 目标

MModel Web UI 面向运维人员提供对象驱动的调查体验，使用户无需命令行即可完成对象定位、关系分析、证据查看、时间线还原和诊断协同。

## 页面结构

在当前这版页面方案中，MModel 建议分为两个一级工作区：

- 实体探索：负责“看清对象”
- 调查结果：负责“沉淀调查结论”

结合目前分工，当前建议不把通用对话助手作为 MModel 主界面，而是先由独立的 Copilot 侧承载。

## 一级页面设计

### 1. 实体探索

实体探索负责围绕对象完成认知、定位与证据调查，建议包含以下标签页或子视图：

- 概览
- 拓扑
- 健康
- 证据
- 调查时间线

各子视图职责如下：

- 概览：展示对象身份、类型、状态、标签、属性、最近活动和关键告警摘要。
- 拓扑：展示上下游关系、依赖链路、影响传播和历史拓扑切换。
- 健康：展示健康评分、异常摘要和关键 SLI / SLO 或核心指标摘要。
- 证据：统一承载 Metrics、Logs、Traces、Events 的聚合视图，并支持以子视图方式切换。
- 调查时间线：以对象为中心统一展示证据事件、拓扑变化和诊断步骤，帮助用户还原故障过程。

### 2. 调查结果

调查结果负责展示结构化调查输出，建议包含以下页面或结果视图：

- 结构化诊断结果
- 影响面分析
- 调查报告

各视图职责如下：

- 结构化诊断结果：展示 AI 诊断结论、疑似根因、证据引用和建议动作。
- 影响面分析：展示受影响对象、服务、业务链路和优先级。
- 调查报告：展示调查摘要、根因结论、证据清单、影响范围、建议与导出。

## MModel vs Copilot 职责边界（当前方案设想）

### 当前建议由 MModel UI 负责

- 对象地图与实体探索入口
- 对象详情与视图切换
- 拓扑浏览与历史拓扑快照
- 健康与证据聚合视图
- 调查时间线视图
- 结构化诊断结果、影响面和调查报告页面

### 当前建议由 Copilot UI 负责

- 通用聊天窗口
- 多轮追问与自然语言解释
- 基于 MModel Skill / MCP / API 的能力调用编排
- 对调查结果、时间线、根因和报告做自然语言摘要与重述

### 协作关系

- 当前建议由 MModel 提供结构化页面与结构化调查上下文。
- 当前建议由 Copilot 调用 MModel 能力，并将结果转化为自然语言交互。
- 结合目前分工，第一阶段暂不把 Copilot 能力直接放入 MModel 项目中。

## 关键交互

- 全局对象搜索
- 时间范围切换
- 从对象概览跳转拓扑
- 从对象概览跳转证据
- 从对象概览跳转调查时间线
- 从时间线事件联动到证据详情
- 从时间线关键时刻联动到拓扑快照
- 从拓扑节点跳转对象详情
- 发起 AI 诊断
- 查看影响面
- 生成调查报告

## 设计原则

- 先对象，后证据。
- 同一对象的概览、拓扑、健康、证据和时间线可以连续切换。
- 在当前方案里，结构化调查结果优先于聊天感界面。
- 平台嵌入与独立访问保持一致的信息结构。
- 参考截图只用于帮助理解目标体验，不要求逐像素复刻。
